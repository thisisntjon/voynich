# Voynich manuscript research record — start here

This repository is the working research record of Simone Systems Research's investigation of the Voynich manuscript (Yale, Beinecke MS 408), handed over so that other researchers, human or AI, can check it, reuse it and go further.

**The manuscript is not deciphered.** Nothing here reads it or names its language. What the work produced is a set of tested structural findings about how the text is built, each graded by how many independent kinds of check agree, plus a long record of explanations and methods that were tried and failed. The failures are the most useful part: they tell you what not to spend time on.

This is a snapshot of the working tree, taken when the research paused (October 2026) and generated by an export script that stays with the private tree. Paths and layout are the tree's own, so the scripts run as written. Internal status pages ([`record/workflow/PLAN.md`](record/workflow/PLAN.md), [`record/workflow/FINDINGS-MAP.md`](record/workflow/FINDINGS-MAP.md) section 0, [`record/TEAM-HANDOFF.md`](record/TEAM-HANDOFF.md)) describe the team at that moment, with its queues and assignments; each carries a snapshot banner, and their "next" actions are historical, not instructions. The team's internal README of 2026-10-17 is kept as [`record/docs/README-internal-2026-10-17.md`](record/docs/README-internal-2026-10-17.md). [`record/MANIFEST.tsv`](record/MANIFEST.tsv) lists every file with its sha256 and whether it was published exactly, with local paths rewritten, or with team-communication references redacted.

New here? Start with [`README.md`](README.md) (summary, headline results, limits, source-of-truth map), then [`FINDINGS.md`](FINDINGS.md), [`DEAD-ENDS.md`](DEAD-ENDS.md) and [`OPEN-QUESTIONS.md`](OPEN-QUESTIONS.md); agents continuing the work alone should read [`CONTINUING.md`](CONTINUING.md). Those pages are generated from the records below. This page is the detailed guide to the records themselves.

## Read the internal records in this order (about 30 minutes)

1. [`record/workflow/FINDINGS-MAP.md`](record/workflow/FINDINGS-MAP.md), **section 0**: the strongest supported finding with its limits, the current next action, and the accepted, disputed and rejected findings. Then section 2 (grades) and section 7 (each finding's evidence lines).
2. [`record/workflow/TRIANGULATION.md`](record/workflow/TRIANGULATION.md): what the grades mean (TRIANGULATED, CORROBORATED, SINGLE, CONTESTED), what counts as an independent axis, and the filing rules every result went through.
3. [`record/.inventory/registers/LEARNINGS.md`](record/.inventory/registers/LEARNINGS.md): findings *and failures*, indexed by theme at the top. [`record/workflow/research/learnings-audit-2026-10-18.md`](record/workflow/research/learnings-audit-2026-10-18.md) has the ten method lessons that bound every later run.
4. [`record/.inventory/registers/DECISIONS.md`](record/.inventory/registers/DECISIONS.md): why things were done, reversed or rejected. D-063 to D-065 explain rejected results; D-072 is the strategy pivot to external validation; D-066 is the run log.
5. [`record/workflow/PLAN.md`](record/workflow/PLAN.md): the `Current stage:` line and the phase log say where the work stopped.
6. [`record/.inventory/registers/CLAIMS.md`](record/.inventory/registers/CLAIMS.md): every cited number, with its source file. [`record/.inventory/registers/OPEN.md`](record/.inventory/registers/OPEN.md): open questions and parked work.

## Reproduce a result

```
cd record
pip install -r requirements-lock.txt  # Python 3.11 (3.12+: requirements-lock-py313.txt); requirements-optional.txt adds torch etc.
python tools/fetch_data.py            # transliterations from voynich.nu, checked against the sha256 our runs used
python tools/build_translit.py        # rebuilds data/translit/*.meta.json byte for byte
python tools/restore_s45_text.py      # puts the transliteration back into the s45 page files
python tools/verify_stubs.py          # checks every pre-registration stub; 0 unexplained lines expected
python s34_morphology_syntax_geography.py   # example; each results_*.txt header names its script and sha256
git diff results_s34_morphology_syntax_geography.txt   # only the clock and run-time lines should change
```

Run scripts from the `record/` folder; they overwrite their own `results_*.txt`, so `git diff` shows what changed. Besides the clock and run-time lines, results files published with local paths rewritten (`rewritten` in [`record/MANIFEST.tsv`](record/MANIFEST.tsv)) also differ in lines that print a path; compare the numbers. roach's replication scripts (`runs/roach-r*`) expect roach's folder layout and inputs: `python tools/roach_layout.py` builds it under `roach-root/`. `python tools/verify_stubs.py` lists the 18 stub lines whose script was edited after pinning; the pinned bytes are kept beside each as `*.orig-<hash>`. A fetched file whose sha256 differs from ours is reported: the source may have been revised since, and results can differ.

Three generated tables say what is not here and how to get it: [`record/NEEDS.tsv`](record/NEEDS.tsv) (data each script reads that is not in the repository, and how to fetch or rebuild it), [`record/WITHHELD.tsv`](record/WITHHELD.tsv) (files a stub names that are not published, with the reason) and [`record/MISSING-EVIDENCE.tsv`](record/MISSING-EVIDENCE.tsv) (files the registers and the findings graph cite that are not here, with the reason).

Runs that need manuscript scans (physical measurements, picture work) need the scan fetch scripts first, and some need a GPU. Image crops, embeddings and other large binaries are not included; the run scripts regenerate them.

## What is not here, and why

- **Team communications** between the research agents (including the reviewer messages `runs/s128/iv/IV-REVIEW-*`; the two pre-registration diffs in that folder are published), and agent configuration files. ([`record/AGENTS.md`](record/AGENTS.md) is kept: it is the working rulebook every agent followed — pre-registration, filing, id rules — so it documents how the results were produced. Its message-routing rules applied inside the team only.)
- **Blind-study material.** Reader inputs, reader responses, sealed keys and grading notes of the blind runs (`runs/s128/blind_review`, s129, s130, s132, s133) are withheld; their protocols, pre-registrations, scripts, fixtures, results and input checksums are included. Stub lines that name withheld files cannot be checked here.
- **Copies of the transliteration.** Run outputs that embed the ZL word stream are withheld or stripped. The s45 page files (`runs/s45/pages/*.json`, our ink geometry from the Yale scans) are published without their two text fields; `python tools/restore_s45_text.py` puts those fields and the two s45 sidecars back, byte for byte, after [`record/tools/fetch_data.py`](record/tools/fetch_data.py), so the stubs that pin them verify again. The s38 sidecars (`runs/s38/*.meta.json`) are withheld; [`record/s38_ink_stream_and_rt2026.py`](record/s38_ink_stream_and_rt2026.py) rebuilds them, but it needs the word-coordinate data, which is not in the fetch list. A few results files quote a handful of transliterated lines as examples. Plain copies of comparison texts are withheld too (`runs/s49/lang_*.meta.json`, rebuilt by [`record/tools/realline_to_meta.py`](record/tools/realline_to_meta.py) from the fetched corpora; `runs/s107/texts.txt`, the MediManus Tacuinum transcription). Enciphered or generated outputs derived from those texts (for example `runs/s64/naibbe_*`) are published: they are our transformations, not readable copies.
- **Third-party data** (transliterations, scans, comparison corpora, papers, models): fetched, not copied, because several licences are unstated or restrictive.
- **Large binaries** (over 5 MB, images, arrays): regenerated by the scripts.

Redactions are marked in place as `<team-comms>`, `<session>` (agent session ids), `<tool-call>`, `<email>` or `<local-path>`. The quotation column of [`record/data/external/q13_colours/q13_page_colours.tsv`](record/data/external/q13_colours/q13_page_colours.tsv) and the summary column of [`record/data/external/library/catalogue_v2.tsv`](record/data/external/library/catalogue_v2.tsv) were removed; each row keeps its source link. Local paths to this tree are rewritten relative to the repository root ([`record/./...`](record/./.../)); paths into the companion lab tree, where some agents worked, become [`record/lab/...`](record/lab/.../), and the lab files the findings and registers cite are included there. Other home-folder paths read `<home>`. The exception is any file whose sha256 a pre-registration stub pins (`exact-pinned` in [`record/MANIFEST.tsv`](record/MANIFEST.tsv)): those are byte-identical so the stub still verifies, and may show the original local paths, team-comms names and agent session ids.

Run the map renderer as `python tools/findings_graph.py render --allow-missing`. Without the flag it stops with 9 "file not found" errors (pointing at 4 distinct files) and writes nothing, because the graph cites our text extractions of four papers (Rozanova and Temerev 2026, arXiv 2608.17096; Parisel 2026, arXiv 2604.19762; Zattera 2022, CEUR-WS vol. 3313 paper 10; library item VL00735). Fetch the papers from their publishers; the extracted text is not redistributed.

Some results also need control texts built from third-party corpora (`data/controls*`, regenerated by [`record/build_controls_ext.py`](record/build_controls_ext.py) and `tools/*_to_meta.py` from fetched sources); without them those cells come out empty.

## Credits

This record rests on other people's work. The transliterations, scans and comparison texts below are fetched from their makers, not copied here (see [`record/data/SOURCES.tsv`](record/data/SOURCES.tsv) for licences and how to get each one). Maker names come from the voynich.nu index (its transliteration README) and the headers of the fetched files.

### Transliterations (fetched by [`record/tools/fetch_data.py`](record/tools/fetch_data.py), listed in [`record/data/FETCH.tsv`](record/data/FETCH.tsv))

**voynich.nu and the IVTFF format.** Every transliteration we use is fetched from René Zandbergen's site, https://www.voynich.nu/data/, where he converted the historical files into his common IVTFF format and documents them (the transliteration README, ivtff.xlsx and the IVTFF format definition). Without this collection, comparing transcribers would not be possible.

**ZL3b (`ZL3b-n.txt`).** The Zandbergen-Landini transliteration by René Zandbergen and Gabriel Landini, version 3b of 13 May 2025, which its header says was updated from the EVMT project. It is our main data source.

**RF1b (`RF1b-e.txt`, `RF1b-er.txt`).** The reference transliteration published on voynich.nu, built automatically by combining the GC (Glen Claston) and ZL (Zandbergen-Landini) transliterations; `-e` keeps extended EVA and `-er` uses basic EVA. The file headers do not name a compiler; it is hosted and documented by René Zandbergen.

**IT2a (`IT2a-n.txt`).** The complete transliteration by Takeshi Takahashi, as included in Jorge Stolfi's interlinear file, converted to IVTFF 2.0 by René Zandbergen.

**VT0e (`VT0e-n.txt`).** Takeshi Takahashi's transliteration in the form used on the voynichese.com site, in IVTFF format.

**GC2a (`GC2a-n.txt`) and voyn_101 (`voyn_101.txt`).** Glen Claston's v101 transliteration: `voyn_101.txt` is his original, unmodified file, and `GC2a` is René Zandbergen's IVTFF version of it.

**CD2a (`CD2a-n.txt`).** The Currier-D'Imperio transliteration (Prescott Currier, with Mary D'Imperio), from the file `voynich.orig`, in Currier's alphabet.

**FG2a (`FG2a-n.txt`).** The transliteration of William Friedman's First Study Group (1940s), in the FSG alphabet, from the file `FSG.txt` as supplied by Jim Reeds (1994); René Zandbergen merged two versions of it.

**LSI (`LSI_ivtff_0d.txt`).** The Landini-Stolfi Interlinear archive, edited by Jorge Stolfi from Gabriel Landini's `INTERLN.EVT` and combining transcriptions by Takeshi Takahashi, John Grove, Jorge Stolfi and the historical transcriptions by William Friedman's group, Prescott Currier, Mary D'Imperio and others re-typed by Jim Reeds, with additions by Jim Gillogly, Mike Roe, Don Latham, John Tiltman and Karl Kluge.

### Manuscript images

The images of the Voynich manuscript are those of Yale University's Beinecke Rare Book and Manuscript Library (Beinecke MS 408), fetched from its IIIF service and stated in the Yale catalog to be in the public domain. The multispectral images of folio 1r were made by the Lazarus Project at the Rochester Institute of Technology and shared through Lisa Fagin Davis; they are not redistributed.

### Languages and hands

The split of the text into two "languages", A and B, and the first hand assignments are Prescott Currier's. The five-scribe hand identification used throughout (IVTFF page variable `$H`) is Lisa Fagin Davis's (2020); voynich.nu records both in the transliteration files.

### Comparison corpora

Control and comparison texts come from: the CREMMA Medieval Latin corpus (HTR-United); Sefaria, Tanzil, the Perseus Digital Library, Wikisource, the Bibliotheca Augustana and Project Gutenberg for the natural-language controls; the Internet Archive's contributing libraries and BIU Santé for period recipe, tabular and ruled-table books; the CoReMa recipe collection; DBNL for the Antidotarium Nicolai; Daniel Gaskell and Claire Bowern's gibberish corpus; Luke Lindemann and Claire Bowern's entropy materials; Michael Greshko's Naibbe cipher supplement; Torsten Timm's text generators (the Timm and Schinner self-citation method); Liudmila Rozanova's word coordinates; Jorge Stolfi's label pages; and the comparison manuscripts of the Bodleian Libraries, the Bayerische Staatsbibliothek, the British Library and the University of Pennsylvania Libraries. Published analyses by Edith Sherwood, Stephen Bax and others, and the papers listed in [`record/data/SOURCES.tsv`](record/data/SOURCES.tsv), are credited where the findings and notes cite them.
